# Cerberus — сводка на 2026-07-04 01:08 EEST

## Цель
Довести Polymarket-бота до стратегии, с которой реально можно вносить деньги
и зарабатывать. Сегодняшняя сессия — диагностика и первый честный замер
эджа на исправленной инфраструктуре.

## Что сделано (хронология)

1. **Синхронизация Mac ↔ GitHub ↔ Windows** — подтянуты вчерашние фиксы с
   Windows-машины (load_dotenv, разделение rejection_reason, HYBRID
   стратегия). Локальная копия на Mac была на 1 коммит позади — синхронизирована.
2. **Реальный баг с охватом рынков** — Gamma API без пагинации отдавал
   только ~20-100 рынков вместо всех активных. Исправлено (пагинация до
   2000 рынков/скан). После этого фикса стало видно: из ~2100 активных
   рынков Polymarket подходят под текущие критерии (бинарные, 1-90 дней до
   резолва, объём $1000-2М/24ч) только **8**.
3. **Панель из 5 независимых агентов** (workflow) разобрала вопрос "как
   реально дойти до прибыльности" и нашла два настоящих бага:
   - БД **не сохраняла** реальные числа edge (edge_gross/edge_net_pct) для
     отклонённых сигналов — только текстовую причину. Без этого нельзя было
     отличить "почти получилось" от "эджа нет вообще". **Исправлено.**
   - Формула комиссии тейкера считала **flat rate**, а не по реальной кривой
     Polymarket `rate × min(price, 1-price) × size` — переплачивала комиссию
     ~2x именно в том ценовом диапазоне ($0.50), где торгует бот.
     **Исправлено.**
   - Панель также дала чёткий вердикт: **не** строить поддержку
     multi-outcome/neg_risk рынков (архитектура жёстко на 2 ноги, полная
     переписка ради непроверенной гипотезы) и **не** снижать пороги эджа
     до появления реальных данных.
4. **Найдена и смягчена причина замедления прогона** — Mac уходил в сон ~93
   раза за ночь (Maintenance/Clamshell Sleep), каждый раз рвал WebSocket и
   тормозил сбор данных в 15-20 раз. Исправлено через `caffeinate`,
   привязанный к процессу прогона — throughput восстановился до нормы
   (~290-390 сигналов/час).
5. **Настроена независимая инфраструктура наблюдения**, не зависящая от
   сессии Claude Code:
   - `launchd` job (`com.cerberus.papermonitor.plist`) — почасовой
     read-only мониторинг, Telegram-алерт только при изменении состояния
     (падение процесса, первый не-FILTERED результат).
   - `tmux`-сессия `cerberus_dashboard` — живой дашборд, можно подключиться
     командой `tmux attach -t cerberus_dashboard`.
   - Починен `dashboard.py` (был жёстко на Windows `tasklist`, теперь
     работает и на macOS).
6. **Запущены параллельно все три метода анализа**, которые есть в
   кодовой базе:
   - **YES+NO арбитраж** (`cerberustest.py`, основной) — 72ч paper run.
   - **Correlation Scanner** — встроен в основной прогон, ищет логические
     противоречия между связанными рынками.
   - **Resolution Arbitrage** (`resolvertest.py`) — отдельный 72ч paper
     run, ищет рынки, где исход уже решён, но цена не подтянулась.
